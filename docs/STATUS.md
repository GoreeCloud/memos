- **Source-scoped Duplicate memo retry protection (merged PR #50, November 8, 2026; `18ca4309`):** The optional canonical UUIDv4 `Idempotency-Key` now also protects authenticated `POST /api/v1/memos/{uuid}/duplicate`, using the existing SQLite replay ledger scoped to the **source memo ID**. A successful new keyed duplicate returns 201, an unchanged replay 200 with the current copy (even if the source is subsequently edited/trashed), while a new request for a missing/trashed source returns 404. A keyed duplicate requires a JSON `{}` body; old no-key clients keep the previous route behavior. The web Duplicate control persists a per-source opaque retry key and fingerprint, blocks concurrent Save/Duplicate button actions, and clears metadata only on confirmed success. The same seven-day, single-database retention and backup/recovery limits apply; it does not provide token revocation or general request idempotency. **Exact-head tests:** 123 Python, 33 Node, 35 Chromium and 35 Firefox synthetic scenarios in PR CI; independent local combined-browser suite 70/70. No real notes, production credentials, hosting changes or device modifications.

- **Atomic memo creation retry protection (merged PR #49, November 8, 2026; `878a3317`):** Optional canonical UUIDv4 `Idempotency-Key` on authenticated `POST /api/v1/memos` creates/replays a memo through one `BEGIN IMMEDIATE` SQLite transaction and stores a key hash, canonical payload digest, memo ID and creation timestamp in `memo_create_requests`. First create returns 201, replay 200 with the **current** memo, same key/different body 409, invalid key 400 and missing original 410. Legacy clients without a key still work. The browser quick-capture/new editor preserves an opaque UUID and cryptographic body/token fingerprint in tab storage for unchanged retries; there is no additional plaintext memo in retry metadata. The request ledger is retained for a **seven-day** window (cleanup on subsequent keyed writes), lives in the single SQLite database, survives full SQLite snapshot backup/recovery, and is schema/reference verified when present; old databases without the ledger remain valid and auto-upgrade on API startup. The v2 JSON export **does not** contain the ledger. **Exact-head checks:** 120 Python tests, 33 Node tests, 33 Chromium and 33 Firefox synthetic scenarios, independently reproduced locally. These are test environments only, not a production deployment or a guarantee for every lost-response scenario, cross-database clients, keys beyond retention, or unrelated mutation routes such as PATCH/DELETE. Source-scoped Duplicate memo POSTs gained the same optional key guarantees in PR #50.

- **Repeated-save and draft-race protection (merged PR #48, November 8, 2026; `13446fbc`):** Quick capture and the modal editor now block repeated POST/submit events until the current write settles. Save controls expose disabled/busy feedback and recover after failed requests; a quick memo typed while an earlier memo is still saving is preserved rather than cleared by that earlier response. Lock invalidates the save-control generation and the existing session-epoch API guard prevents late response effects. The client guard is not a server-side idempotency mechanism and cannot prevent duplicate writes from separate tabs/devices, retries after an ambiguous server commit, or nonbrowser callers. Exact-head PR standard CI passed **112 Python + 33 Node** tests and browser acceptance passed **30/30 Chromium + 30/30 Firefox** synthetic scenarios; an independent full local Playwright run also passed 60/60, including new rapid-submission and draft-race tests. No real memo data was used and no production deployment was attempted.
- **Post-mockup privacy hardening (merged PR #46, November 8, 2026; `bed7d5a6`):** Browser Lock aborts tracked protected fetches and invalidates all late responses using a per-session epoch and token check, including previously pending plaintext export, revisions and mutation responses. An older failed login cannot clear a newer token; Lock clears transient toast content, closes the compact menu and focuses the token field. The mobile overflow menu now opens below the complete search header, dismisses on Escape/outside click and returns focus; unsafe 200 responses with malformed JSON or an unexpected v2 export schema cannot be downloaded as purported backups. **Client cancellation cannot undo a mutation the server already committed, and browser lock is not server-side token revocation.** Exact-head standard CI passed 112 Python and 33 Node cases, plus **23/23 Chromium and 23/23 Firefox** browser cases. The merged source's two GitHub workflows also passed; no real credentials or private data were used.
