# GoreeCloud Memos — Implementation Status (2026-11-07)

**Classification:** active development preview. Not production-qualified or deployed.
**Repository:** GoreeCloud/memos (actual casing lowercase).
**Product:** GoreeCloud Memos.

## Implemented in the development workspace

- SQLite-backed memo creation, read, update, duplicate, archive, trash and restore.
- Optional titles, hashtag extraction, colors, pinning, revision history, version-conflict protection, filtering and full v2 JSON export (all memos plus revisions, without the home-feed cap). Hashtag-filtered feed results are streamed and bounded to 2,000 matching records, including older notes after unrelated records.
- One-server-token bearer authentication, no unsecured fallback, localhost-only binding default. HTTP API authentication now uses bounded, per-socket-peer failure throttling (default eight failures/60 seconds; HTTP 429 during lockout), with atomic threshold/count accounting across request threads. Accepted development HTTP sockets now have a 15-second idle read timeout; incomplete authenticated JSON bodies can receive HTTP 408 without modifying SQLite, while stalled headers close. This remains a process-local development control, not production-grade distributed rate limiting. The Python CLI and GTK4 client explicitly reject automatic redirects and configured HTTP proxies for bearer-token requests and require HTTPS for non-loopback destinations; GUI runtime validation remains pending. The browser client now explicitly applies `redirect: error`, `mode: same-origin`, `referrerPolicy: no-referrer`, `credentials: omit` and no-store caching to token-bearing API calls (merged PR #30); Node tests check fetch options and mocked rejection. Separate Chromium/Firefox tests (merged PR #41) confirm redirect refusal across **different loopback origins** using a fictional bearer token and zero requests to the test target; this is not public TLS or external-network penetration testing.
- **GC UI C36 skeleton loading for authenticated memo feeds (merged PR #28, November 7, 2026):** Shape-matched, decorative, non-animated memo placeholders appear only when an authenticated feed load takes longer than 120ms; they are hidden before login and during the locked state. A labeled busy region exposes loading while keeping live status outside it. New filters clear stale private cards immediately; superseded/locked fetches cannot repopulate the view. Empty, network-error, offline, and 12-second timeout outcomes resolve into meaningful states with retry. HTTP 401 on authenticated refresh locks the workspace and clears private memo DOM; unsaved tab drafts remain untouched. The change is local to the Memos web source and uses existing GC UI-aligned tokens, not a verified released shared component or native implementation.
- Responsive web home with **default Pinterest-style masonry**, variable-height cards, separate pinned section, alternative list view, GC UI-aligned Iris colors, search, tags, editor, drafts and theme switch. A confirmed **Clear drafts** control is available before or after login, removing only Memos-owned unsaved sessionStorage draft keys from the current tab without touching saved server notes, token state or layout/theme preferences. **Lock** forgets the browser tab's bearer token, closes the editor, invalidates pending feed renders and removes displayed memo text without deleting drafts; the tab can be freshly authenticated to restore an unsaved quick draft. Visible focus indicators cover keyboard-focused cards and search/quick-capture containers, and reduced-motion preferences disable card hover movement.
- Python CLI: create, list with folder/text/hashtag filters, duplicate a memo, read a single memo (`show UUID`), inspect previous revisions (`history UUID`), restore prior title/content as a **new current version** (`restore-revision UUID --version N`), reversible pin/unpin, archive/unarchive and trash/restore actions with optimistic version guards and no-op detection, version-guarded update, JSON export to stdout, and optional owner-only atomic POSIX JSON export via `export --output PATH` (exclusive 0600 file, no overwrite, failure cleanup). Memo-specific CLI commands require canonical lowercase UUIDs. Displayed or exported memo text remains plaintext, not encrypted. Standalone local maintenance tool: consistent online SQLite backup, integrity and memo-history relationship verification (including rejection of missing revision versions), and fail-closed non-overwriting restore. Automated regression coverage includes committed uncheckpointed WAL data and injected file/directory flush failures. Completed copies are flushed before exclusive publication; POSIX parent-directory metadata is flushed after publication, with best-effort cleanup on failure.
- Browser Export now warns that the JSON download contains all memos (including archive/trash) and full prior revision history, and requires affirmative confirmation **before** requesting any plaintext export data. Browser downloads do not enforce CLI private-file permissions or encryption.
- Browser editor: safe basic Markdown preview, rendering headings, fenced code, paragraphs, quotes, lists and allowlisted HTTPS/HTTP links; preview checkboxes update the in-session draft, then require explicit save. Existing memo editors also include lazy-loaded, text-only prior revision previews with an explicitly confirmed, optimistic-version-guarded restoration that creates a new current version and warns about unsaved drafts.
- **CI synthetic backup/restore drill (merged PR #38):** `python3 server/recovery_drill.py` creates only fictional data in a cleaned temporary directory, verifies revision-preserving recovery, isolation from later source edits, no-overwrite publication and POSIX mode 0600. The GitHub CI job runs it independently of the unit tests. It does not schedule or encrypt real backups or prove disaster recovery.
- **Coherent read-only verification (merged PR #39):** one explicit SQLite read transaction covers every integrity, schema, history and count query. A deterministic test commits fictional writes between count queries and verifies the result remains one WAL snapshot.
- **Repository-specific open-source license (merged PR #40):** complete Apache-2.0 `LICENSE`, GoreeCloud/GC UI provenance `NOTICE`, `docs/LICENSE_ASSESSMENT.md`, README and npm metadata are on main. This is an assessed source license, not a blanket grant for third-party code or a product release.
- Native Linux GTK4 initial client: note display in separate variable-height vertical columns, search, create and edit.
- Recovery verifier rejects missing or reordered SQLite primary-key constraints on `memos(id)` and `revisions(memo_id, version)`, plus existing logical history corruption; it does not repair or rewrite an invalid source database.
- POSIX-only private SQLite provisioning helper: creates private 0700 intermediate/final directories and a 0600 empty database file, refuses symlinks in any directory component and the final file, and uses descriptor-relative no-follow operations instead of resolving mutable ancestor paths. It refuses unsafe existing final-directory or database permissions and does not overwrite existing content. Pre-existing ancestor permissions, ACLs and hostile local renames remain outside its verified scope. The recommended `server/serve_private.py` development launcher validates the token before disk changes, sets umask 077, invokes this helper, and binds only to IPv4 loopback. On existing database files it performs read-only schema, integrity and complete revision-history checks **before** server initialization, failing closed rather than silently rebuilding missing tables. Legacy `server/app.py` startup remains available but **does not automatically enforce these protections**; see [private storage](PRIVATE_STORAGE.md).

The real local API cases additionally verify invalid dummy-token rejection, valid login, synthetic memo POST and readback across reload, and a **simulated** 401 refresh followed by lock/re-login and retained tab drafts. The first run identified a narrow-screen Firefox overflow fixed before acceptance. Evidence: [PR #33](https://github.com/GoreeCloud/memos/pull/33), [PR #34](https://github.com/GoreeCloud/memos/pull/34), [PR #35](https://github.com/GoreeCloud/memos/pull/35) and [issue #32](https://github.com/GoreeCloud/memos/issues/32). ## Development priorities

1. Continue hardening the storage/API, token policies, migrations, authenticated rate limits and **production-scale recovery/fault-injection drills**; the disposable synthetic backup/restore CI rehearsal is implemented.
2. Extend the safe Markdown subset and interactive checklist preview, then implement attachment scanning/quotas and metadata.
3. Extend native clients, starting with Android, and verify Linux usability.
4. Design and test accounts, permissions and collaboration.
5. Implement sync, reminders, MCP/AI and cross-app integrations.

The default-masonry acceptance criterion is that a clean browser with no layout preference sees adaptive variable-height cards; list mode is optional and locally persistent. This is implemented for the web client. The GTK client uses a preliminary masonry-inspired independent-column layout, pending visual QA.

**Deployment is blocked** until separately authorized and reviewed for TLS, identity, secrets, backups, recovery, rate limits, permissions, observability and rollback.
